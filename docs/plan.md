## 1. Концепция

### EKT Match — ассистент подбора автомата и аналога

**Пользователь:** прораб электромонтажной бригады, который срочно комплектует объект.

**Боль:** он пишет менеджеру: «Нужен автомат 3P C16, 10 kA, 8 штук; если нет — совместимый аналог». Менеджер отвечает не сразу, а неверный аналог рискует сорвать монтаж или создать техническую ошибку.

**Один завершённый сценарий:**

1. Пользователь вводит технический запрос в чат.
2. Ассистент извлекает параметры: полюса, характеристику, номинал, отключающую способность, количество.
3. Система ищет точный товар в demo-каталоге.
4. Если точного товара нет или остаток недостаточен, показывает до двух совместимых аналогов и объясняет различия.
5. Пользователь выбирает вариант.
6. Только явное нажатие **«Подтвердить и добавить в корзину»** добавляет SKU в корзину.
7. Корзина показывает SKU, количество и сумму.

### Что не делаем

- Оплату, личный кабинет, реальную ERP/складскую интеграцию.
- Универсальный чат по всему каталогу, голос, многоязычность.
- Поиск по внешнему сайту во время демо.

### Технический минимум

- React + Vite + TypeScript.
- Express API.
- Локальные `data/catalog.json` и `data/demo-cache.json`.
- Zod для строгой валидации AI-структуры.
- Vitest для сценариев подбора и подтверждения.
- Одна команда запуска: `npm run dev`.

## 4. API-бюджет и архитектура AI

### Распределение

| Провайдер | Задача | Лимит вызова |
|---|---|---|
| **NVIDIA NIM** | Превращает пользовательский запрос в строгий JSON: `poles`, `curve`, `amps`, `breakingCapacity`, `quantity` | `meta/llama-3.1-8b-instruct`, максимум 180 выходных токенов, один вызов на новый запрос |
| **OpenAI** | Формирует короткое объяснение, почему аналог подходит, только из карточек, найденных системой | Малая доступная модель, максимум 140 выходных токенов, `temperature: 0` |
| **Локально** | Поиск по каталогу, проверка совместимости, корзина, fallback-ответы | 0 затрат |

### Лимиты

- Soft cap: **$10 OpenAI** и **$10 NVIDIA**.
- Hard cap в приложении: **$20 у каждого провайдера**; дальше автоматически включается offline mode.
- Кэшировать по нормализованному запросу.
- Не использовать фоновые запросы, стриминг или циклы повторной генерации.
- На демо использовать один заранее проверенный запрос и его закэшированную копию.

### Критичный принцип

LLM **не выбирает SKU и не придумывает характеристики**. Он только структурирует запрос или формулирует объяснение. Товары, цены, наличие и совместимость поступают только из локального каталога и детерминированных правил.

## 5. Питч — 90 секунд

### 0:00–0:27 — проблема

> Прорабу нужно сегодня заказать восемь автоматов 3P C16 на объект. Он знает характеристики, но не знает остатки и совместимые аналоги. Сейчас он пишет менеджеру, ждёт ответ и рискует взять неподходящую замену. Один такой вопрос тормозит закупку и монтажную бригаду.

### 0:27–1:12 — демо

Ввести заранее подготовленный запрос:

> Нужен автомат 3P C16, 10 kA, 8 штук. Если нет — совместимый аналог.

Показать строго по порядку:

1. Ассистент распознал параметры.
2. Точный товар отсутствует или его остаток недостаточен.
3. Есть два подходящих аналога с остатком и объяснением.
4. Выбрать один товар.
5. Показать, что корзина ещё не изменилась.
6. Нажать «Подтвердить и добавить в корзину».
7. Показать SKU, 8 штук и сумму в корзине.

### 1:12–1:30 — итог

> EKT Match превращает технический запрос в проверяемый подбор по каталогу и безопасное действие в корзине. Для клиента — заказ за минуты; для EKT — меньше ручных ответов менеджеров и меньше незавершённых покупок. Demo-каталог можно заменить реальным API наличия без изменения основного сценария.

## 7. Риски и fallback

| Риск | Профилактика | Что показать на демо |
|---|---|---|
| NVIDIA/OpenAI недоступен | `data/demo-cache.json`, `APP_MODE=offline` | Включить offline mode; результат совпадает с основным сценарием |
| Модель выдумала SKU | SKU берутся только из JSON-каталога; Zod валидирует AI-ответ | Показать карточку с данными из локального каталога |
| Интернет нестабилен | Все зависимости, данные, скриншоты и слайды локальны | Локальный сервер и offline mode |
| Точного товара нет | Это часть сквозного сценария: показать аналоги | Использовать заранее подготовленный запрос |
| Ошибка корзины | Локальная корзина без внешнего API | Перезапустить demo и повторить подтверждение |
| README не работает | В 17:00–17:25 сделать чистый запуск по README на втором ноутбуке | Показать успешный чистый запуск |
| Не успели слайды | Только три слайда: проблема, решение/архитектура, эффект | Демонстрировать продукт, а не слайды |
