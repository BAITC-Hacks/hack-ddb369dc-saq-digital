# EKT Match — SAQ Digital

Помощник для подбора автоматических выключателей: принимает запрос по
характеристикам или артикулу, показывает цену и остаток, предлагает кандидатов
в аналоги и добавляет товар в корзину после явного подтверждения.

Проект объединяет React-интерфейс, Express API и каталог из 40 синтетических
SKU. Основной сценарий работает локально без интернета, аккаунтов и API-ключей
после установки зависимостей.

## Быстрый запуск

Требуется **Node.js 22.10+** и npm. Проверено на Node.js 24.11.1 и npm 11.6.2.
Команды выполняются из корня репозитория в Windows, macOS или Linux:

```sh
npm run setup
npm run dev
```

Откройте **http://localhost:5173**. Команда запускает Backend и Vite вместе;
запросы `/api` проксируются на Backend. Остановка — `Ctrl+C`.
Frontend обновляется через Vite; после изменения Backend перезапустите общую
команду. Отдельный режим watch Backend: `npm --prefix backend run dev`.

`setup` устанавливает Frontend через существующий lock-файл, а Backend — без
создания lock-файла, согласно правилам репозитория. Backend нужен также для
интеграционных тестов Frontend.

## Собранное приложение

```sh
npm run build
npm start
```

Откройте **http://localhost:3001**. Express раздаёт API и готовый Frontend,
включая `/cart`. Vite для этого режима не требуется. `npm run preview`
запускает тот же режим. Открывайте сборку через сервер, а не как локальный
HTML-файл: интерфейс обращается к API.

## Структура проекта

```text
frontend/                 React + TypeScript + Vite
  src/components/         Чат, карточка товара, страница корзины
  src/lib/                Клиент API и форматирование
  src/test/               Подключение Backend для тестов интерфейса
  config.json             Порт UI, адрес API и demo-запрос
  package-lock.json       Существующий lock-файл Frontend
backend/                  Express + Zod, JavaScript ESM
  src/                    API, каталог, подбор, сессии, корзина, адаптеры
  test/                   Тесты Backend и интеграция с demo-данными
  config.json             Порт, пути данных, настройки адаптеров
  purchase-terms.json     Локальный снимок условий со ссылкой на источник
data/catalog.json         Общий каталог: 40 синтетических SKU
docs/                     Контракты, сценарии, описание интеграции
scripts/dev.mjs           Общий запуск приложения
package.json              Команды setup, dev, build, start, test
.env.example              Необязательные настройки окружения
```

```text
Браузер → Frontend → /api → Backend → data/catalog.json
                              ├── поиск и правила подбора
                              ├── контекст сессии
                              └── корзина в памяти
```

Backend валидирует каталог через Zod и преобразует `price` → `priceKzt`,
`breakingCapacity` → `breakingCapacityKa`. Frontend получает товары только от
API и переводит числовые параметры в подписи карточек. Отдельного каталога
заглушек в интерфейсе нет.

## Проверка демо

1. Нажмите **Demo** в помощнике. Запрос: `Нужен автомат 3P C16, 10 kA, 8 штук. Если нет — совместимый аналог.`
2. Точный товар `DEMO-MCB-001` имеет остаток 3 штуки и недоступен для этого
   количества. Есть два кандидата с 15 kA: `DEMO-MCB-003` и `DEMO-MCB-004`.
3. Выберите `DEMO-MCB-003`. До подтверждения корзина остаётся пустой;
   **Отмена** также ничего в неё не добавляет.
4. Нажмите **Подтвердить и добавить**, затем **Перейти в корзину**.
5. На `/cart` проверьте SKU `DEMO-MCB-003`, **8 штук**, цену **7 900 ₸** и
   сумму **63 200 ₸**.
6. Обновление страницы в той же вкладке сохраняет корзину, пока работает
   Backend. После перезапуска Backend создаётся новая пустая сессия.

Дополнительные запросы: `Есть DEMO-MCB-013, 4 штуки?`,
`Какие условия доставки и оплаты?`, `4P D63, 15 kA, 1 штука`.
Все десять сценариев: [docs/demo-catalog.md](docs/demo-catalog.md).

## Настройки

Файл `.env` необязателен. При необходимости скопируйте `.env.example` в `.env`
в корне. Команды `dev` и `start` загружают его автоматически.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `APP_MODE` | `offline` | `live` разрешает настроенные внешние адаптеры |
| `PORT` | `3001` | Порт Backend; Vite использует его для proxy |
| `FRONTEND_PORT` | `5173` | Порт Vite |
| `CATALOG_PATH` | `data/catalog.json` | Абсолютный путь или путь относительно рабочей директории процесса |
| `FRONTEND_DIST_PATH` | `frontend/dist` | Абсолютный путь или путь относительно `backend/` |
| `CART_URL` | `/cart` | Путь страницы корзины Frontend |
| `VITE_API_BASE_URL` | `/api` | Адрес API отдельно размещённого Frontend; задаётся при сборке |
| `NVIDIA_API_KEY` | Не задан | Необязательный ключ NIM в `live` |
| `NVIDIA_MODEL` | Из `backend/config.json` | Модель извлечения параметров |
| `NVIDIA_CHAT_COMPLETIONS_URL` | Из `backend/config.json` | Endpoint NIM |
| `EKT_API_USERNAME`, `EKT_API_PASSWORD` | Не заданы | Необязательный доступ к чтению карточек партнёра в `live` |
| `EKT_PRODUCT_DETAIL_URL` | Из `backend/config.json` | Endpoint карточки партнёра |

В `offline` работает локальный парсер. В `live` NIM используется только если
локальный разбор не распознал запрос; модель не выбирает SKU и не меняет корзину.
У адаптера есть кэш в памяти и лимит 20 вызовов на процесс из конфигурации.
Денежный бюджет и интеграция OpenAI не реализованы.

Обновление партнёрских карточек требует реальных `id` в каталоге; у синтетических
SKU их нет. При недоступности партнёра сохраняются локальные данные.
Ключи и пароли храните только в окружении или локальном `.env`.

## Тесты

```sh
npm test
npm run build
```

Backend проверяется встроенным `node:test`, Frontend — Vitest и Testing Library.
Тесты интерфейса поднимают настоящий Express API с общим каталогом. Проверяются
все 10 demo-запросов в одной сессии, единицы измерения, изоляция корзин,
явное подтверждение, отсутствие мутаций при отмене и ошибках, повтор после
потери ответа, восстановление сессии и страница корзины.

## Технологии и данные

| Компонент | Использование |
|---|---|
| React 19, TypeScript 5.7, Vite 6 | Интерфейс и сборка |
| Express 5, Zod 4 | HTTP API и валидация |
| Vitest 2, Testing Library, jsdom 25 | Проверки интерфейса |
| Node.js `node:test` | Проверки Backend |
| Phosphor Icons | Иконки интерфейса |
| NVIDIA NIM | Необязательное извлечение параметров в `live` |
| `data/catalog.json` | Синтетические данные команды, не выгрузка ekt.kz |
| `backend/purchase-terms.json` | Снимок условий; ссылка на источник содержится в файле и ответе API |

## Границы демо

Товары, цены и остатки вымышлены. Упрощённые правила подбора не устанавливают
реальную техническую взаимозаменяемость оборудования. Корзина хранится в памяти
Backend, не резервирует склад и не оформляет заказ на ekt.kz. Оплата, загрузка
файлов, авторизация покупателя и сохранение в БД не реализованы. Окружение
витрины служит контекстом для работающего помощника и локальной корзины.
