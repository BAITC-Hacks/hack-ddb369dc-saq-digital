# EKT Match — SAQ Digital

Помощник для подбора автоматических выключателей: принимает запрос по
характеристикам или артикулу, показывает цену и остаток, предлагает кандидатов
в аналоги и добавляет товар в корзину после явного подтверждения.

Проект объединяет React-интерфейс, Express API и каталог из 40 синтетических
SKU. Основной сценарий работает локально без интернета, аккаунтов и API-ключей
после установки зависимостей или сборки Docker-образа.

## Запуск одной кнопкой через Docker

Установите и запустите Docker Desktop с Linux-контейнерами и Docker Compose v2+.
В Windows откройте **`start.cmd` двойным кликом**: он соберёт приложение,
запустит его в фоне и дождётся успешной проверки готовности. Локальные Node.js
и npm для этого не нужны. Первый запуск загружает образ Node.js и зависимости.

Та же команда для Windows, macOS, Linux и сервера:

```sh
docker compose up --build --wait --remove-orphans
```

Откройте **http://localhost:8080**. В Docker Desktop появится проект `ekt-match`
с двумя сервисами: `frontend` (Nginx и интерфейс) и `backend` (Express, каталог,
OpenAI и корзина). Backend доступен внутри сети Docker; Frontend передаёт ему
запросы `/api`. Повторный запуск применяет изменения к тому же проекту и удаляет
прежний общий контейнер `app`. После первой сборки запускать и
останавливать проект можно кнопками Docker Desktop.

```sh
docker compose logs -f frontend backend
docker compose down
```

Если порт занят, измените `APP_PORT` в корневом `.env` и повторите запуск.
Есть эквивалентные команды npm: `docker:up`, `docker:logs`, `docker:down`.
Подробности образа, окружения и размещения на сервере: [docs/deployment.md](docs/deployment.md).

## Разработка без Docker

Требуется **Node.js 22.10+** и npm. Проверено на Node.js 24.11.1 и npm 11.6.2.
Команды выполняются из корня репозитория в Windows, macOS или Linux:

```sh
npm run setup
npm run dev
```

Откройте **http://localhost:5173**. Команда запускает Backend и Vite вместе;
запросы `/api` проксируются на Backend. Остановка — `Ctrl+C`.
Frontend обновляется через Vite; после изменения Backend перезапустите общую
команду. Отдельный режим watch Backend: `npm --prefix backend run dev`.

`setup` устанавливает Frontend через существующий lock-файл, а Backend — без
создания lock-файла, согласно правилам репозитория. Backend нужен также для
интеграционных тестов Frontend.

## Собранное приложение

```sh
npm run build
npm start
```

Откройте **http://localhost:3001**. Express раздаёт API и готовый Frontend,
включая `/cart`. Vite для этого режима не требуется. `npm run preview`
запускает тот же режим. Открывайте сборку через сервер, а не как локальный
HTML-файл: интерфейс обращается к API.

## Структура проекта

```text
frontend/                 React + TypeScript + Vite
  src/components/         Чат, карточка товара, страница корзины
  src/lib/                Клиент API и форматирование
  src/test/               Подключение Backend для тестов интерфейса
  config.json             Порт UI, адрес API и demo-запрос
  package-lock.json       Существующий lock-файл Frontend
backend/                  Express + Zod, JavaScript ESM
  src/                    API, каталог, подбор, сессии, корзина, адаптеры
  test/                   Тесты Backend и интеграция с demo-данными
  config.json             Порт, пути данных, настройки адаптеров
  purchase-terms.json     Локальный снимок условий со ссылкой на источник
data/catalog.json         Общий каталог: 40 синтетических SKU
docs/                     Контракты, сценарии, описание интеграции
deploy/Dockerfile          Отдельные образы Frontend и Backend
deploy/nginx.conf.template Раздача UI и proxy /api к Backend
scripts/dev.mjs           Общий запуск приложения в разработке
compose.yaml              Запуск Docker, порт, окружение, перезапуск
start.cmd                 Запуск Docker двойным кликом в Windows
package.json              Команды разработки, проверок и Docker
.env.example              Необязательные настройки окружения
```

```text
Браузер → frontend (Nginx) → /api → backend (Express)
                                      ├── data/catalog.json и правила подбора
                                      ├── OpenAI: вопросы о сайте и диалог
                                      └── сессии и корзины в памяти
```

Backend валидирует каталог через Zod и преобразует `price` → `priceKzt`,
`breakingCapacity` → `breakingCapacityKa`. Frontend получает товары только от
API и переводит числовые параметры в подписи карточек. Отдельного каталога
заглушек в интерфейсе нет.

## Проверка демо

В `live` можно начать с «что по товарам есть», «Как выбрать товар на сайте?»
или «Чем отличаются характеристики B и C?». Помощник получает факты каталога
и историю диалога, отвечает на вопросы магазина и отклоняет посторонние темы.
Для подбора можно написать «Нужны трёхполюсные автоматы C16 на десять килоампер»,
затем ответить «восемь штук» на вопрос о количестве. Сначала проверяются
известные локальные сценарии, остальные вопросы понимает OpenAI.

1. Нажмите **Demo** в помощнике. Запрос: `Нужен автомат 3P C16, 10 kA, 8 штук. Если нет — совместимый аналог.`
2. Точный товар `DEMO-MCB-001` имеет остаток 3 штуки и недоступен для этого
   количества. Есть два кандидата с 15 kA: `DEMO-MCB-003` и `DEMO-MCB-004`.
3. Выберите `DEMO-MCB-003`. До подтверждения корзина остаётся пустой;
   **Отмена** также ничего в неё не добавляет.
4. Нажмите **Да, добавить**. После подтверждения сервером откроется корзина.
5. На `/cart` проверьте SKU `DEMO-MCB-003`, **8 штук**, цену **7 900 ₸** и
   сумму **63 200 ₸**.
6. Обновление страницы в той же вкладке сохраняет корзину, пока работает
   Backend. После перезапуска Backend создаётся новая пустая сессия.

Дополнительные запросы: `Есть DEMO-MCB-013, 4 штуки?`,
`Какие условия доставки и оплаты?`, `4P D63, 15 kA, 1 штука`.
Все десять сценариев: [docs/demo-catalog.md](docs/demo-catalog.md).

## Настройки

Файл `.env` необязателен. При необходимости скопируйте `.env.example` в `.env`
в корне. Команды `dev`, `start` и Docker Compose читают настройки из него.
Существующий `.env` обновляйте вручную, чтобы сохранить свои значения.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `APP_MODE` | `offline` | `live` разрешает настроенные внешние адаптеры |
| `PORT` | `3001` | Порт Backend внутри контейнера и в локальной разработке |
| `APP_PORT` | `8080` | Опубликованный порт Docker на хосте |
| `FRONTEND_PORT` | `5173` | Порт Vite |
| `CATALOG_PATH` | `data/catalog.json` | Абсолютный путь или путь относительно рабочей директории процесса |
| `FRONTEND_DIST_PATH` | `frontend/dist` | Путь для общего сервера без Docker, относительно `backend/` |
| `CART_URL` | `/cart` | Путь страницы корзины Frontend |
| `VITE_API_BASE_URL` | `/api` | Адрес API для отдельно размещённого Frontend при локальной сборке; Docker использует общий `/api` |
| `OPENAI_API_KEY` | Не задан | Необязательный ключ OpenAI в `live` |
| `OPENAI_MODEL` | `gpt-4.1-mini` | Модель диалога и извлечения параметров с Structured Outputs |
| `OPENAI_RESPONSES_URL` | Из `backend/config.json` | Endpoint OpenAI Responses API |
| `FRONTEND_IMAGE` | `ekt-match-frontend:local` | Образ интерфейса |
| `BACKEND_IMAGE` | `ekt-match-backend:local` | Образ API; старый `APP_IMAGE` принимается как fallback |
| `BACKEND_ORIGIN` | `http://backend:3001` | Адрес API для Nginx в Docker; порт берётся из `PORT` |
| `EKT_API_USERNAME`, `EKT_API_PASSWORD` | Не заданы | Необязательный доступ к чтению карточек партнёра в `live` |
| `EKT_PRODUCT_DETAIL_URL` | Из `backend/config.json` | Endpoint карточки партнёра |

Для OpenAI укажите в `.env`:

```dotenv
APP_MODE=live
OPENAI_API_KEY=ваш_ключ_OpenAI
```

Повторите `docker compose up --build --wait --remove-orphans` после изменения `.env`.
Ранее использовавшиеся `NVIDIA_*` больше не нужны. `OPENAI_MODEL` и endpoint
можно не задавать: значения по умолчанию находятся в `backend/config.json`.
Ключ передаётся только Backend во время запуска и не попадает в Docker-образ
или JavaScript интерфейса.

В `offline` работают локальные подбор, вопросы по артикулу и условиям покупки.
В `live` свободные вопросы классифицирует OpenAI: получает текущий каталог,
условия покупки, состояние корзины текущей сессии, последние 8 сообщений и уже
уточнённые параметры. Формулировки о товарах, ценах, корзине и проверенных
технических сведениях сервер строит из этих данных; неподтверждённые факты из
свободного текста модели не показываются покупателю.
Это диалог по данным сайта, без перебора заранее записанных вопросов.
Посторонние темы перенаправляются к магазину и не попадают в дальнейшую историю
модели. При подборе неизвестные характеристики остаются `null`; помощник
спрашивает только о недостающих данных. Карточки и цены формирует поиск Backend.
Модель не может изменять корзину текстовым ответом. Подбор использует только
характеристики, которые пользователь явно назвал в текущем запросе или сохранил
при уточнении; новый подбор сбрасывает прежние параметры.

У адаптера есть кэш с учётом контекста (до 256 ответов, срок 60 секунд), лимит
20 вызовов модели за 60 секунд, 768 выходных токенов и таймаут 15 секунд.
Неудачные попытки тоже расходуют лимит; автоматических повторов нет. Дополнительно
действуют лимиты на сессию и источник запроса: 6 AI-вызовов на сессию и 10 на IP
за минуту, для анонимного поиска — 2 на IP. Параметры находятся в
`backend/config.json` и имеют значения по умолчанию в коде. Денежный бюджет
OpenAI в приложении отдельно не рассчитывается.

Сессии истекают после 30 минут бездействия; одновременно хранится до 1000.
Создание ограничено 30 запросами в минуту на IP, заполненная ёмкость отвечает
`SESSION_CAPACITY` без удаления активной корзины. В Docker Nginx проксирует
запросы с общего адреса шлюза, поэтому IP-лимит может суммироваться для всех
посетителей. `trustProxy=false` по умолчанию защищает от подделки
`X-Forwarded-For`; для публичного многопользовательского развёртывания настройте
точный список доверенных прокси и подходящие лимиты в `backend/config.json`.
При недоступности AI локальный поиск по артикулу и параметрам продолжает работать.

Обновление партнёрских карточек требует реальных `id` в каталоге; у синтетических
SKU их нет. При недоступности партнёра сохраняются локальные данные.
Ключи и пароли храните только в окружении или локальном `.env`.

## Тесты

```sh
npm test
npm run build
```

Backend проверяется встроенным `node:test`, Frontend — Vitest и Testing Library.
Тесты интерфейса поднимают настоящий Express API с общим каталогом. Проверяются
все 10 demo-запросов в одной сессии, единицы измерения, изоляция корзин,
явное подтверждение, отсутствие мутаций при отмене и ошибках, повтор после
потери ответа, восстановление сессии и страница корзины. В обычный запуск включены
регрессии из [аудита](docs/audits/2026-09-23/report.md); результаты исправлений
описаны в [проверке после исправлений](docs/audits/2026-09-23/fixes.md).

## Границы демо

Товары, цены и остатки вымышлены. Упрощённые правила подбора не устанавливают
реальную техническую взаимозаменяемость оборудования. Корзина хранится в памяти
Backend, не резервирует склад и не оформляет заказ на ekt.kz. Оплата, загрузка
файлов, авторизация покупателя и сохранение в БД не реализованы. Окружение
витрины служит контекстом для работающего помощника и локальной корзины.

Команда: **SAQ Digital**. [Описание интеграции](docs/integration.md),
[контракт API](docs/backend-api.md).
