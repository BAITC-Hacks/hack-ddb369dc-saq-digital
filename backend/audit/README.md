# Проверки устойчивости и ошибочных ответов

Это материалы аудита, а не исправления приложения. Проверенная версия: `e373a326aff28a8066b88900aabd8a82afd5414b`. Отчёт и сохранённые результаты: [23 сентября 2026](../../docs/audits/2026-09-23/report.md).

Используются уже установленные зависимости проекта, `node:test`, Vitest и стандартная библиотека Node. Новые пакеты не нужны. Команды выполняются из корня репозитория.

## Регрессии без внешних запросов

```powershell
node --test backend/audit/regressions.mjs

$env:EKT_RUN_AUDIT = '1'
npm --prefix frontend test -- src/audit.test.tsx
$env:EKT_RUN_AUDIT = $null
```

На проверенной версии ожидаются **23 ошибки backend и 3 ошибки frontend**: тесты проверяют правильное поведение и документируют текущие дефекты. Это не зелёные тесты, закрепляющие ошибочную реализацию. После исправлений соответствующие проверки должны проходить. Они запускаются отдельно: обычный `npm test` проходит 115 штатных тестов и пропускает три opt-in проверки интерфейса.

Изолированные HTTP-серверы получают свободный порт от ОС; OpenAI в этих тестах заменён управляемым ответом. Данные корзины и история создаются только внутри тестового процесса.

## Параллельные запросы и ограниченная проверка памяти

```powershell
node backend/audit/resilience.mjs "$env:TEMP\ekt-resilience-result.json"
```

Проверяются 1000 созданий сессий, 400 поисков, конкурентные записи в корзину, подтверждение, остатки и ошибочные запросы. Затем отдельный дочерний процесс создаёт синтетические сессии с лимитом old-space 64 MiB, пределом 100000 сессий и таймаутом 15 секунд. На исходной версии дочерний процесс падает по памяти; результат сохраняется, основной процесс завершается. Это не нагрузка на работающие контейнеры. `old-space` не означает ограничение всей памяти процесса.

## Реальная модель — платный, явный запуск

```powershell
node --env-file=.env backend/audit/live.mjs "$env:TEMP\ekt-live-result.json"
```

Запускается отдельный экземпляр приложения: сессии и лимит работающего Docker backend не расходуются. Скрипт делает 22 диалоговых запроса, максимум 20 вызовов OpenAI, без повторных попыток. Он требует настроенный `OPENAI_API_KEY`, официальный endpoint и `gpt-4.1-mini`. До отправки каждого запроса проверяется консервативная оценка суммарной стоимости до $1. Это программная оценка по указанным в скрипте тарифам, не финансовый лимит аккаунта; при изменении тарифов её нужно пересмотреть.

Ответы и фактические токены сохраняются в JSON. Ключ и заголовки авторизации не записываются. Ответы модели могут отличаться между запусками; завершение скрипта с кодом 0 означает сбор результатов, а не отсутствие ошибок AI. Для исходного запуска ручные оценки приведены в отчёте и `live-verdicts.json`. Сначала сравнивайте сохранённые результаты, затем при необходимости повторяйте платную проверку.

Браузерные сценарии выполнены в отдельном временном профиле Chrome через штатный DevTools Protocol. Шаги подмены JSON, проверки HTML и восстановления после потери ответа описаны в отчёте; новые браузерные фреймворки в проект не добавлялись.
