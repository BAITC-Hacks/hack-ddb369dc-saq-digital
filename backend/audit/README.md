# Проверки устойчивости и ошибочных ответов

Это материалы аудита, а не исправления приложения. Проверенная версия: `e373a326aff28a8066b88900aabd8a82afd5414b`. Отчёт и сохранённые результаты: [23 сентября 2026](../../docs/audits/2026-09-23/report.md).

Используются уже установленные зависимости проекта, `node:test`, Vitest и стандартная библиотека Node. Новые пакеты не нужны. Команды выполняются из корня репозитория.

## Регрессии без внешних запросов

```powershell
node --test backend/audit/regressions.mjs

$env:EKT_RUN_AUDIT = '1'
npm --prefix frontend test -- src/audit.test.tsx
$env:EKT_RUN_AUDIT = $null
```

На исходной проверенной версии `e373a32` эти команды давали **23 ошибки backend и 3 ошибки frontend**. После исправлений все 26 проверок должны проходить. Три frontend-регрессии также включены в обычный `npm test`; переменная `EKT_RUN_AUDIT` оставлена для явного запуска на исторической версии.

Изолированные HTTP-серверы получают свободный порт от ОС; OpenAI в этих тестах заменён управляемым ответом. Данные корзины и история создаются только внутри тестового процесса.

## Параллельные запросы и ограниченная проверка памяти

```powershell
node backend/audit/resilience.mjs "$env:TEMP\ekt-resilience-result.json"
```

Проверяются 1000 попыток создания сессий, 400 поисков, конкурентные записи в корзину, подтверждение, остатки и ошибочные запросы. За минуту из одного источника создаются 30 сессий, 970 запросов получают 429. Затем отдельный дочерний процесс делает 20000 попыток создания синтетических сессий при old-space 64 MiB и таймауте 15 секунд. На исправленной версии хранятся 1000 сессий, остальные попытки отклоняются без OOM. Это не нагрузка на работающие контейнеры. `old-space` не означает ограничение всей памяти процесса.

## Реальная модель — платный, явный запуск

```powershell
node --env-file=.env backend/audit/live.mjs "$env:TEMP\ekt-live-result.json"
# Ограниченный повтор критических сценариев:
node --env-file=.env backend/audit/live.mjs "$env:TEMP\ekt-live-focused.json" L01,L02,L03,L06,L07,L10,L14,L15,L16,L17,L18,L19,L20,L21,L22
```

Запускается отдельный экземпляр приложения: сессии и лимит работающего Docker backend не расходуются. Без третьего аргумента скрипт делает 22 диалоговых запроса; третий аргумент выбирает ID через запятую. Число вызовов ограничено как `maxCalls<=20`, так и лимитами самого приложения; без повторных попыток. Скрипт требует настроенный `OPENAI_API_KEY`, официальный endpoint и `gpt-4.1-mini`. До отправки каждого запроса проверяется консервативная оценка суммарной стоимости до $1. Это программная оценка по указанным в скрипте тарифам, не финансовый лимит аккаунта; при изменении тарифов её нужно пересмотреть.

Ответы и фактические токены сохраняются в JSON. Ключ и заголовки авторизации не записываются. Ответы модели могут отличаться между запусками; завершение скрипта с кодом 0 означает сбор результатов, а не отсутствие ошибок AI. Для исходного запуска ручные оценки приведены в отчёте и `live-verdicts.json`. Сначала сравнивайте сохранённые результаты, затем при необходимости повторяйте платную проверку.

Браузерные сценарии выполнены в отдельном временном профиле Chrome через штатный DevTools Protocol. Шаги подмены JSON, проверки HTML и восстановления после потери ответа описаны в отчёте; новые браузерные фреймворки в проект не добавлялись.
